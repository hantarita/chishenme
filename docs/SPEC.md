# 「吃什么」校园食堂点评推荐：需求梳理与 Spec

## 1. Context

大学生每天都要决定“食堂吃什么”，却没有针对校园食堂的点评工具。本项目以北大家园食堂二层为例，做一个 3D 点评推荐工具，帮学生发现新菜、避开踩雷窗口。

这是面试作品，评审只看一个公开链接，所以有三个硬约束：

- 链接公开、可长期访问，域名不变。
- 面试官打开后不用注册，马上能用。
- 优先呈现产品结构和功能设计，不追求技术深度。

仓库目前是空的，只有 README、LICENSE 和 .gitignore，没有可复用的代码。

### 已确认的决策

| 问题 | 决定 | 带来的影响 |
|---|---|---|
| 部署 | GitHub Pages，地址 `https://hantarita.github.io/chishenme/` | 只能托管静态文件，不能运行服务器代码 |
| 数据 | 种子数据 + 浏览器存储 | 新评论只保存在写评论者的浏览器里，其他人看不到 |
| 范围 | 只做二层档口区，约 12 个档口 | 精力集中在一个空间 |
| 档口名单 | 保留“北京味道”，其余虚构，页面标注 | 全站显示“档口、菜品和评论均为演示数据” |

### 需要知道的两个限制

- **“后端”运行在浏览器里。** GitHub Pages 没有服务器，后端是一层模拟 API，接口形式和真实后端一致。之后要接真实后端时，只需替换这一层。
- **大陆访问未经验证。** `github.io` 在大陆也可能不稳定，我这里无法实测。提交前请用大陆网络打开一次。所有资源都打包在站内，不依赖外部 CDN，可减少一部分风险。

## 2. 需求梳理

| # | 你的需求 | Spec 中的做法 |
|---|---|---|
| R1 | Three.js 模拟食堂空间，像 food court | 3D 二层大厅：沿墙档口、中央餐桌区、立柱、楼梯口 |
| R2 | 画出所有档口，并显示名字招牌 | 每个档口有 3D 门头招牌，中文清晰可读 |
| R3 | 热力图：最高分最红，0 分为白色 | 档口颜色随评分连续变化，配图例 |
| R4 | 档口综合评分 0–5 星 | 招牌、悬浮提示和详情页都显示 |
| R5 | 像大众点评一样写评论、打分 | 档口详情内发表评论，提交后评分、颜色和榜单立即更新 |
| R6 | 点开档口看最高分和最低分的五个菜，不足则显示前三 | 按 §4.3 规则显示，两个榜单不重复 |
| R7 | 右侧栏：菜品上新 + 综合榜前五 | 常驻右侧栏，点击飞到对应档口 |
| R8 | 每个菜标注辣或不辣 | 菜品出现的所有位置都显示标签 |
| R9 | 转盘随机抽取不同档口的菜 | 每次抽 6 道菜，来自 6 个不同档口，结果可跳转 |

## 3. 页面结构

```
┌────────────────────────────────────────────────────────┐
│ 吃什么 · 北大家园食堂二层 [演示数据]      [🎡 不知道吃什么] │
├──────────┬──────────────────────────────┬──────────────┤
│ 档口详情  │                              │ 🆕 菜品上新   │
│ (点击后   │       3D 食堂空间             │              │
│  滑出)    │                              │ 🏆 综合榜 Top5│
│          │  [热力图例 0 ▢▒▓█ 5]          │              │
└──────────┴──────────────────────────────┴──────────────┘
```

手机端：上方为 3D 视图，榜单在其下方；详情面板约占屏幕下半部分，打开时页面回到顶部，让 3D 画面和档口变色保持可见。页面不出现横向滚动。

### 核心流程

1. **逛食堂：** 看颜色 → 悬浮看名字和评分 → 点击档口 → 镜头飞近，详情滑出。
2. **避雷：** 详情中查看“推荐菜”和“评价最低”两个榜单。
3. **写评论：** 选菜（或评价档口整体）→ 打星 → 写评论 → 颜色和榜单立即变化。这是演示时最有效果的一步。
4. **选择困难：** 打开转盘 → 可选“全部 / 只要辣 / 不要辣” → 转动 → 查看结果 → 去这个档口。

## 4. 功能规则

### 4.1 评分

- 一条评论必须打 1–5 星，0 星只表示“没有评论”。
- 菜品评分 = 该菜所有评论的平均分。
- 档口评分 = 该档口所有评论的平均分，包括评价菜品和评价档口整体的评论；保留一位小数。
- 没有评论时，评分记为 0，显示“暂无评分”。

### 4.2 热力图

- 使用绝对刻度，按 0–5 分连续渐变：`0 #FFFFFF → 1.5 #FEE0D2 → 3 #FC9272 → 4 #EF3B2C → 5 #99000D`。单一红色系不会和木地板、木桌混在一起。
- 颜色作用于档口主体和地面光晕；招牌文字根据底色自动选择深色或浅色，保证可读。
- 种子数据要覆盖 0 到 4.8 分，让热力差异一眼可见，并至少有一个新开档口为 0 分（白色）。

### 4.3 档口的推荐菜与评价最低榜

只统计有评论的菜，设数量为 N：

| N | 推荐菜 | 评价最低 |
|---|---|---|
| N ≥ 10 | 前 5 | 后 5 |
| 6 ≤ N ≤ 9 | 前 3 | 后 3 |
| N ≤ 5 | 前 ⌈N/2⌉（最多 3） | 剩下的 ⌊N/2⌋ |

最后一行是为了防止同一道菜同时上两个榜，你的原始需求没有覆盖这种情况。详情中另设“全部菜品”，让暂无评论的菜也能被评价。

### 4.4 综合榜 Top 5

- 排序使用贝叶斯加权分：`(v·R + m·C) / (v + m)`，其中 v 为评论数，R 为平均分，C 为全站平均分，m = 5。
- 这样可以避免只有一条五星评论的菜直接登顶。
- 榜单显示真实平均分和评论数。
- 档口内部的两个榜单按真实平均分（四舍五入前）排序，不用加权分。否则评论少的 5.0 分菜会出现在“评价最低”里。

### 4.5 菜品上新

- 显示上架 14 天内的菜，最新的在前，最多 6 道。
- 种子数据保存“几天前上架”，打开页面时再换算成日期。否则链接放久了，上新栏会变空。

### 4.6 转盘

- 每次从不同档口各抽一道菜，共 6 道，可点“换一批”。
- 可筛选“全部 / 只要辣 / 不要辣”；符合条件的档口少于 2 个时给出提示。
- 先用随机数确定结果，再让动画停在对应扇区，保证结果与指针一致。
- 结果卡片显示菜名、档口、评分、辣度和“去这个档口”。
- 系统开启“减少动态效果”时，跳过旋转动画。

### 4.7 评论

- 字段：昵称（默认“匿名同学”）、评价对象、星级（必填）、内容（5–300 字）。
- 不需要登录。用户可以删除自己写的评论。
- 右上角提供“重置演示数据”，用于清除本机写入的评论。

### 4.8 3D 空间

- 约 40m × 28m 的大厅：12 个档口沿三面墙呈 U 形排列，中央为餐桌区，入口处有楼梯。
- 使用低多边形模型和统一材质，保证普通笔记本流畅运行。
- 环境细节（木地板、窗户、标语、回收台、饮水台、绿植、餐具、学生）只用非红色系，避免和热力图混淆；也不在档口上方放横梁或吊灯，以免挡住招牌。档口只有屋顶、墙身、打菜台和雨棚使用热力色。
- 档口前的排队人数随评分变化（0 分没人，最多 4 人），这是装饰，不是真实客流。
- 招牌用 Canvas 绘制成贴图，使用系统中文字体，不需要下载字体文件。
- 镜头可旋转和缩放，但限制角度和范围，防止钻到地板以下或飞出大厅。
- 不支持 WebGL 时，自动退回 2D 平面图，颜色和点击逻辑相同。运行中 WebGL 上下文丢失时也切到平面图，但保留切回 3D 的入口。键盘用户也可以通过档口列表访问。

## 5. 技术方案

**技术栈：** Vite + React + TypeScript + Three.js（通过 `@react-three/fiber`、`drei`）+ Zustand，测试用 Vitest 和 Playwright。

选择 Vite 而不是 Next.js，因为产物是纯静态文件，最适合 GitHub Pages。

```
src/
  scene/      3D 大厅、档口、招牌、镜头（前端）
  ui/         详情、右侧栏、转盘、评论表单、图例（前端）
  api/        模拟后端：client.ts 定义接口，mockServer.ts 实现（带模拟延迟）
  domain/     纯函数：评分、排序、榜单切分、转盘抽样、热力色
  data/       seed/*.json + storage.ts（localStorage 读写）
scripts/generate-seed.ts   固定随机种子，生成可复现的演示数据
.github/workflows/deploy.yml
docs/SPEC.md
```

### 模拟 API

```ts
getStalls(): StallSummary[]              // 含评分、评论数、热力色输入
getStall(id): StallDetail                // 含推荐榜、避雷榜、全部菜品
getReviews(stallId): Review[]
createReview(input): Review
deleteReview(id): void                   // 只能删除本机写入的评论
getNewDishes(): Dish[]
getTopDishes(limit = 5): RankedDish[]
drawWheel({ spicy }): WheelDish[]
resetLocalData(): void
```

UI 只能通过这层 API 取数据，不能直接读种子文件或 localStorage。

### 数据模型

```ts
Stall  { id, name, slotIndex, cuisine, intro }
Dish   { id, stallId, name, price, spicy: boolean, listedDaysAgo }
Review { id, stallId, dishId | null, author, stars: 1..5, text, createdDaysAgo | createdAt, isLocal }
```

- 种子规模：12 个档口，约 100 道菜，约 400 条评论。
- 档口的菜品数要覆盖 §4.3 的三种情况。
- 所有档口、菜品和评论都是虚构的，且全站标注，避免被误认为对真实档口的评价。
- localStorage 键带版本号。读写失败（如无痕模式）时退回内存存储，页面仍可使用。

目前可用的 skills 中没有前端、后端或 Three.js 专用的。所以我会用 `skill-creator` 在 `.claude/skills/` 下建三个轻量项目 skill，写入本 spec 的约定，不额外跑评测：

|---|---|---|

## 8. 验证

**单元测试（Vitest）**
- 榜单切分：N = 0、1、2、5、6、9、10，两榜不重复。
- 贝叶斯排序：单条五星的菜不能排在大量高分评论的菜之前。
- 热力色：0 分为 `#FFFFFF`，5 分为 `#99000D`，颜色随分数单调变化。
- 转盘：抽到的菜来自不同档口，筛选结果正确，档口不足时有提示。
- 存储：写入后可恢复，存储不可用时不报错。

**端到端测试（Playwright，针对 `vite preview` 的 `/chishenme/` 路径）**
- 页面加载无控制台报错，资源路径无 404。
- 发表评论后，档口评分和榜单更新；刷新后评论仍在；重置后恢复。
- 转盘结果可以跳转到正确的档口。
- 手机宽度下没有横向滚动，禁用 WebGL 时显示 2D 平面图。

**人工检查**
- 查看 3D 截图：招牌中文清晰，白色到红色的差异明显。
- 部署后在无痕窗口打开线上链接，走完 §3 的四个流程。
- **需要你做：** 提交前用大陆网络打开一次。
